# Data dictionary - synthetic retail-bank loan applications

100% generated by `python -m src.data.make_dataset` (seeded, deterministic, no downloads).
`data/raw/applications.csv`: **12,000 rows x 26 columns**, one row per loan application (2022-01-01 .. 2023-12-31). Amounts are in INR.

**Target** `default_12m` = 1 if the borrower defaulted within 12 months of disbursal (about **11.3%** of rows).
**Prediction moment** = the instant the application is submitted. A column is a legal model input only if it already exists then.

Legend for "Use": **INPUT** = eligible input (the model uses the subset chosen by `select_features.py`), **AUDIT** = used only for fairness audits, **BLOCKED** = must never reach the model (reason given).

## 1. Columns known at application time

| Column | Type | Meaning | Use | Notes / why |
|---|---|---|---|---|
| applicant_id | id (string) | Person identifier, e.g. `A000123` | split only | About 7% of applications are **re-applications** by the same person (same id). Used to keep one person out of both train and test. |
| application_date | date | Day the application was submitted | split + monitoring | Basis of the **time-based split** (oldest 70% train, next 15% valid, newest 15% test). |
| age | int | Applicant age in years (21-65) | AUDIT (governance-flagged) | Restricted or regulated in lending in many countries; **excluded by default**. A *policy* decision for Compliance, not a technical one. See `src/governance/age_experiment.py`. |
| annual_income | float | Annual income *declared by the applicant* | INPUT (via `log_income`) | **~12.2% missing, not at random** (MNAR-ish: self-employed / business owners and high earners skip it more). A few x10 data-entry errors. Right-skewed (skewness 20.8; 0.2 after log). |
| monthly_income | float | Average monthly credits in the last 3 months | INPUT (correlated) | Always present but noisy. Spearman correlation with annual_income about 0.89 (Pearson only ~0.65 because of the outliers) -> one of the pair is dropped. |
| employment_years | float | Years in current job/business | INPUT | |
| loan_amount | float | Requested amount | INPUT | |
| loan_term_months | int | Requested tenure (12, 24, 36, 48, 60) | INPUT (weak) | |
| credit_history_years | float | Years since first credit account | INPUT | A few thin-file applicants (< 1 year). |
| bureau_score | float (300-900) | Credit-bureau score | INPUT | **~8.1% missing** - thin-file applicants have no score. Missing is informative (`bureau_score_missing`). |
| existing_loans | int | Open loans at other lenders | INPUT | |
| monthly_debt | float | Total monthly EMIs on existing loans | INPUT (correlated) | |
| debt_to_income_ratio | float | `monthly_debt / monthly_income` | INPUT | Correlated with monthly_debt (Spearman 0.81): keep the ratio, drop the amount. |
| number_of_dependents | int | Financial dependents | INPUT (weak) | |
| employment_type | category | salaried / self_employed / gig / business | INPUT | One-hot encoded. |
| education | category (ordered) | school < diploma < graduate < postgraduate | INPUT (weak) | Ordinal encoded. |
| location | category (15 cities) | City of the applicant | **BLOCKED (governance)** | **Proxy risk**: in this data some cities have more women applicants *and* a local economic effect, so `location` can stand in for gender. Excluded; see fairness table "before / after removing proxies". |
| gender | category | female / male | AUDIT only | **Sensitive.** Never a model feature and **not part of the API request**. Used by `fairness_audit.py`. |
| marital_status | category | single / married / divorced | BLOCKED (sensitive) | Protected in many jurisdictions. |

## 2. Columns that exist in the raw file but must be rejected (and why)

| Column | Why it is not allowed | Type of problem |
|---|---|---|
| interest_rate_offered | Set **after** risk scoring (riskier customers get higher rates) - it is a function of the score and of the outcome. | **Target leakage** (AUC jumps from ~0.77 to ~0.94) |
| loan_approved | The historical **decision** itself - an output of the old process, not an input. Using it is circular. | Leakage / circularity |
| days_past_due_after_disbursal | Only known months **after** the loan is paid out; defaulters have large values. | **Look-ahead** (AUC ~1.0) |
| collections_status | Created by the collections team *because* the customer stopped paying. | Look-ahead |
| post_disbursal_payment_ratio | Share of EMIs paid in the first 6 months - future information. | Look-ahead |
| credit_officer_override | A human step **after** the model score, informed by later knowledge. | Not available at prediction time / circular |

## 3. Features we engineer (all in `src/features/build_features.py`)

| Feature | Formula | Why it helps |
|---|---|---|
| log_income | `log(1 + annual_income)` | Income is right-skewed; log makes it symmetric and tames outliers. NaN stays NaN (median-imputed inside the Pipeline). |
| loan_to_income | `loan_amount / annual_income` | A loan of 3 lakh is small for a 12-lakh earner and huge for a 3-lakh earner. |
| emi_estimate | `P*r*(1+r)^n / ((1+r)^n - 1)`, r = 14%/12 | Monthly burden of the new loan. The 14% rate is an **assumption** - the real rate is only decided after scoring (using it would be leakage). |
| emi_to_income | `emi_estimate / monthly_income` | Share of monthly income the new loan takes. |
| debt_service_ratio | `(monthly_debt + emi_estimate) / monthly_income` | Share of monthly income going to all debts after this loan. |
| income_missing / bureau_score_missing | 1 if the value is missing | Missingness itself carries signal. |
| employment_stability | bucket of employment_years: lt_1y / 1_3y / 3_7y / 7y_plus | Non-linear "job stability" view. |
| credit_history_bucket | bucket of credit_history_years: thin / young / established / long | Same, for credit history. |
| city_tier | tier1 / tier2 / tier3 from the city | Coarse replacement of `location` (lower proxy risk). |

## 4. Real-world problems injected on purpose

| Problem | Where / how much | Where you meet it |
|---|---|---|
| Missing values, MNAR-ish | annual_income ~12%, bureau_score ~8% | `profile_data.py` section 4, median imputation + indicators |
| Correlated features | income pair (Spearman 0.89), monthly_debt vs DTI (0.81) | correlation table, `select_features.py` |
| Outliers | ~0.2% of incomes multiplied by 10 | IQR rule, log transform |
| Class imbalance | 11.3% defaulters | AUC / KS / PR-AUC instead of accuracy |
| Leakage columns | 6 columns above | `leakage_demo.py`, registry gate, `tests/test_leakage.py` |
| Sensitive / proxy | gender, marital_status, age, location | fairness audit, review gate |
| Repeat applicants | ~7% of rows | applicant-level split |
| Drifting world | `batch_normal.csv` (credit histories slowly lengthen: significant but small) and `batch_drifted.csv` (economic downturn: incomes down, DTI up, bureau scores lower, **and** the old rules weaken) | drift check, retraining |

## 5. Production batches (`data/production/`)

`batch_normal.csv` (3,000 applications, Apr-Sep 2024, same world + a slow shift) and `batch_drifted.csv` (3,000, downturn). Columns = the API request fields + `applicant_id`, `application_date`, the audit-only `age`, `gender`, and the TRUE `default_12m` - which in real life would arrive **12 months later**. `data/processed/reference.csv` = 3,000 rows of the training-time model-input frame (the drift reference).

**How the true default rule works (generator, simplified):** `logit = b0 + 0.5*z_dti + 0.8*z_loan_to_income - 0.3*z_income - 0.45*latent_creditworthiness + ...`, `p = 1/(1+exp(-logit))`, `default = 1 if U < p`. Example: logit = -2.2 gives p = 1/(1+e^2.2) = 0.10. Because the generator is known, a model AUC near 0.77 is *about as good as honest modelling can get* here, and an AUC of 0.95 can only be leakage.
