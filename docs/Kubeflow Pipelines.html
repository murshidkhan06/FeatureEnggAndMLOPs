01 · Why pipelines
A notebook trains a model once; a pipeline trains it the same way every time
Notebook
✗ Cells run by hand, in an order only the author knows
✗ Works on one laptop with one set of packages
✗ No record of which data and settings made which model
✗ Retraining on new data means someone repeats it all
→
Pipeline
✓ Steps form a graph that runs itself, in the right order
✓ Each step runs in its own container with pinned packages
✓ Every run records its inputs, outputs, metrics and logs
✓ Re-run on a schedule or a trigger, with new parameters
In the course map this is the retrain loop: drift detected → run the pipeline again → promote only if better.

02 · How KFP works
A component is a Python function that runs in its own container
@dsl.component(base_image="python:3.9")      # ① def load_data(output_csv: Output[Dataset]):   # ②     import subprocess     subprocess.run(["pip", "install",         # ③         "pandas", "scikit-learn"], check=True)     from sklearn.datasets import load_iris   # ④     import pandas as pd     iris = load_iris()     df = pd.DataFrame(data=iris.data,                       columns=iris.feature_names)     df['target'] = iris.target     df.to_csv(output_csv.path, index=False)   # ⑤
① base_image · the container the step runs in
② Output[Dataset] · KFP hands you a path for the file this step produces
③ pip at run time · packages install inside the pod, every run
④ imports inside · only the function body ships to the container
⑤ write to .path · KFP uploads the file as an artifact
From kubeflow_pipeline.py · shortcut for ③: packages_to_install=["pandas", "scikit-learn"] in the decorator

02 · How KFP works
The pipeline function wires steps together; KFP works out the order
@dsl.pipeline(name="ml-pipeline") def ml_pipeline():     load_op = load_data()     preprocess_op = preprocess_data(         input_csv=load_op.outputs["output_csv"])     train_op = train_model(         train_data=preprocess_op.outputs["output_train"],         ytrain_data=preprocess_op.outputs["output_ytrain"])     evaluate_op = evaluate_model(         test_data=preprocess_op.outputs["output_test"],         ytest_data=preprocess_op.outputs["output_ytest"],         model=train_op.outputs["model_output"])
Order from data
evaluate waits for preprocess and train, because it uses both outputs
Outputs by name
The key in .outputs[…] is the Output argument's name
No parameters yet
ml_pipeline() takes no arguments, so the run form is empty
More when you need it
dsl.If gates, dsl.ParallelFor loops, step caching

04 · Hands-on lab
Step 3: install Kubeflow Pipelines 2.17 with three kubectl commands
export PIPELINE_VERSION=2.17.0 # ① cluster-scoped resources kubectl apply -k \   "github.com/kubeflow/pipelines/manifests/kustomize/cluster-scoped-resources?ref=$PIPELINE_VERSION" # ② wait for the Application resource type kubectl wait --for condition=established --timeout=60s crd/applications.app.k8s.io # ③ the Pipelines platform itself kubectl apply -k \   "github.com/kubeflow/pipelines/manifests/kustomize/env/platform-agnostic?ref=$PIPELINE_VERSION" kubectl get pods -n kubeflow -w  # wait until all are Running, then Ctrl+C
① Cluster-scoped
Namespace kubeflow, custom resource types (Application, Argo Workflow, ScheduledWorkflow) and cluster roles
② Wait
Until Kubernetes accepts the new types; skip it and ③ fails with "no matches for kind"
③ Platform-agnostic
API server, UI, Argo, MySQL, SeaweedFS, metadata, cache; no cloud account needed
Source: kubeflow.org, KFP standalone installation · first install takes several minutes while images download

05 · Production and recap
When the lab breaks, it is usually one of five things
Symptom
Likely cause
Fix
Pods stay Pending or get OOMKilled
Cluster too small
minikube delete, start with 4 CPUs / 8 GB
"no matches for kind Application"
Step ③ ran before the CRD was ready
Rerun the wait, then rerun ③
Some pods in CrashLoopBackOff
MySQL or storage not up yet
Wait a few minutes; check kubectl logs if it persists
Confusion-matrix PNG not in the UI
It is saved beside metrics_output; only the artifact file is uploaded
Give the plot its own Output artifact and save it to that .path
Step stuck, ImagePullBackOff or pip errors
minikube can't reach Docker Hub or PyPI
Check network or proxy; step logs show the error
First stop for any step: click it in the UI → Logs. Second: kubectl get pods -n kubeflow.
