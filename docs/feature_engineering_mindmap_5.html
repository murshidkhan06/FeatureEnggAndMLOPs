Text Features

A checklist of words instead of a sentence a model can't read

Text normalization

Bag of Words

TF-IDF

N-grams

Sparsity

Vocabulary pruning

PHASE 4Feature Selection

Filter Methods

Sorting the toy box with quick rules, no playing

Variance threshold

drop a column that's 99% the same value

Correlation filter

attendance_pct and its near-duplicate copy — drop one

Chi-square / ANOVA

does course really affect pass/fail?

Mutual information

catches non-linear links the other tests miss

Wrapper Methods

Actually testing squads in real practice rounds

RFE

train, drop the weakest feature, repeat

Forward / backward

start empty, add the single best feature each round

Computational cost

RFE retrains the model 10 times; a filter test runs once

Model dependency

Logistic Regression and Random Forest pick different top features

Embedded Methods

A toy box that tidies itself while you play

Lasso (L1)

shrinks a useless column's weight to exactly zero

ElasticNet

keeps two correlated features together, instead of picking one

Tree importance

Random Forest ranks study_hours as most useful

Stability of selection

same top features chosen across 50 resamples of the data

SHAP values

Global vs local

Each phase flows into the next: clean the data (Phase 2) before creating new signal from it (Phase 3), create before selecting what's worth keeping (Phase 4), and reduce dimensionality (Phase 5) only once you know what survived selection. Phase 3 now covers feature creation across every raw data type — time, text, images, and domain-driven business behavior — and Phase 4 pairs classic selection methods with the importance/interpretability tools that answer the same "what actually matters?" question. Phase 6 is where all of this meets the real world: keeping features honest (no leakage), reproducible (pipelines), documented (metadata), and reliably served (feature stores).
Where Feature Engineering Hands Off to MLOps
The exact same pipeline, followed end to end — dataset in, live URL out
Raw dataset (.csv) → Feature Engineering (Phases 1–6) → sklearn Pipeline trained → MLflow tracking → model.joblib + Model Registry → FastAPI (/predict) → Streamlit UI → Docker image → GitHub Actions: test → build → push → Docker Hub → AWS EC2 / Kubernetes (live) → Prometheus + Grafana → Drift detection → Kubeflow pipeline: retrain & promote → ↺ Back to Feature Engineering

This is not a one-way line — it's a loop. Drift detection on live traffic feeds straight back into re-running Phases 1–6 on fresh data, retraining, and re-deploying. Closing the loop back to Feature Engineering

The MLOps half picks up exactly where Feature Engineering leaves off: a trained sklearn.Pipeline is tracked (Phase 9) before it's ever trusted, packaged as model.joblib and served by exactly one process — FastAPI (Phase 10) — so a Streamlit UI, a Docker container, and an AWS server can all reach the same predictions through the same door. Docker (Phase 11) freezes that whole environment so it behaves identically on a laptop, in CI, and on AWS EC2. None of this is separate from Feature Engineering — Phase 12's drift detection exists specifically to notice when the world has drifted away from the features Phase 1–6 were built on, which is exactly when the retrain loop sends you back to the start.

PHASE 18 · NEWML Security

Defence

Model Theft

Artifact theft

Defence

Adversarial Attacks

Defence

The third row turns a deployed model into an operated one. GitHub Actions (Phase 13) tests every change and ships the exact Docker image that runs in production. Prometheus and Grafana (Phase 14) watch the running system. Kubeflow Pipelines (Phase 15) turn the whole lifecycle into an automated, retrainable workflow. Governance (Phase 16), Explainability (Phase 17) and ML Security (Phase 18) are not final steps: they apply across the whole map, from the Phase 6 leakage checklist and Phase 9 registry approvals to audit trails linking every prediction to its commit, data and model version.
